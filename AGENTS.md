# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project Purpose

This repository powers https://mgifford.github.io as **Project Atlas**: a curated
catalogue of repositories owned by mgifford, extended with a public, evidence-backed
activity dashboard.

The site has three goals:

- Public portfolio view for curated, high-signal projects.
- Public activity view answering "what changed recently, who did it, and what is still
  open?" from normalized GitHub events.
- Owner maintenance view for identifying unfinished work (open PRs, stale issues,
  README quality, archived state). Owner mode is disabled in the public deployment.

## Core Principles

- Keep the site fully static and GitHub Pages compatible.
- Keep curation human-editable in YAML.
- Keep generated files deterministic and machine-written.
- Separate public signals from owner-only maintenance signals.
- Activity is public-only. Never read notifications, private repositories, or
  authenticated-only endpoints into published data.
- Evidence over inference. Activity rows must link to a GitHub source and must not be
  derived from repository names or descriptions.
- Deterministic before generative. No LLM is required to use or build the dashboard.
- Avoid adding server-side runtime dependencies.

## Agent Operating Rules

1. Respect manual curation.
- Do not overwrite data/curation.yml structure unless asked.
- Preserve manual overrides and featured lists.

2. Treat generated files as build output.
- Regenerate instead of hand-editing files under data/generated/ when possible.
- If scripts change output schema, update build-site-data.mjs and frontend usage together.

3. Keep owner mode safe.
- Never commit personal tokens, credentials, or session data.
- Owner mode token use must remain browser-local.

4. Keep workflows lightweight.
- Weekly job: repository sync, bounded activity collection, data and static-page builds.
- Monthly job: screenshot refresh and site-data rebuild.
- Activity collection has a hard request budget and a 20-minute workflow timeout.
- Avoid adding AI-dependent cron jobs unless explicitly requested.

5. Prefer incremental, readable changes.
- Keep scripts composable.
- Avoid broad rewrites when a small patch is enough.

6. Treat activity data as evidence.
- Preserve event ids, timestamps, actors, roles, automation status, outcomes, and
  source URLs.
- Do not infer accomplishments from repository activity. Opened != shipped; merged !=
  deployed.
- When a source is unavailable or partial, publish that status. Never present missing
  data as inactivity.
- Respect the request budget and retention policy in `data/workstreams.yml` and
  `scripts/collect-activity.mjs`.

7. Generated pages are build output.
- `activity.html`, `contributions.html`, `workstreams.html`, `reports.html`,
  `sitemap.xml`, and `reports/activity/*.md` are generated by
  `scripts/build-pages.mjs`.
- Edit `src/views.mjs`, `src/render.mjs`, or `scripts/build-pages.mjs`, then run
  `npm run build:all`. Do not hand-edit the generated HTML.
- The static HTML must remain meaningful without JavaScript. Interactive controls are
  hidden until the enhancement script succeeds.

8. Keep time handling centralized.
- Use `src/time.mjs` for range boundaries and formatting.
- The configured reporting time zone is `America/Toronto` by default.
- Never add 24-hour arithmetic for calendar weeks; DST makes them 167 or 169 hours.

## Common Commands

Install dependencies:

```bash
npm install
```

Run full pipeline (requires `GH_TOKEN` for collection):

```bash
npm run sync:all
```

Individual steps:

```bash
npm run sync:repos
npm run sync:activity
npm run build:data
npm run build:pages
```

Rebuild merged frontend data and static pages:

```bash
npm run build:all
```

Capture screenshots:

```bash
npm run screenshot:pages
```

Run local static server:

```bash
npm run start
```

## Commit and PR Conventions

Use clear, scoped messages that describe intent and impact.

Commit message style:

- Prefer conventional prefixes such as `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`.
- Keep subject line concise and action-oriented.
- Mention affected area when useful, for example: `feat(ui): add owner impact dashboard`.

Pull request title style:

- Use a short scope in square brackets followed by a plain-language summary.
- Format: `[scope] Short description`
- Examples:
  - `[catalog] Improve curated homepage defaults`
  - `[automation] Capture screenshots only for changed repos`
  - `[docs] Clarify token scopes for workflows`

PR checklist expectations:

- Run relevant validation commands before opening or merging.
- Update related docs when behavior or policy changes.
- Keep generated-file updates tied to script or pipeline changes.

## Data Contract Expectations

Each repo record consumed by the frontend should include:

- identity: name, fullName, url
- status: archived, fork, visibility
- metrics: stars, watchers, openIssues, updatedAt
- metadata: language, topics, description, homepage, hasPages
- enrichment: readme summary and quality signal (including hasAiDisclosure)
- aiQuality: hasAgentsMd, hasCopilotInstructions, scannedAt
- curation overlay: theme, featured flag, optional screenshot, optional highlight
- presentation overrides when curated: cardTitle, cardSummary, featuredNarrative, manualSortRank, visibility

If this contract changes, update scripts and frontend together in the same change.

Each activity event consumed by the frontend should include:

- identity: stable `id`, `repository`, `url`
- source: `eventType`, `category`, `source`, `retrievedAt`, `timestamp`
- attribution: `actor`, `actorRole`
- automation: `automated`, optional `automationReason`
- reporting: `outcome`, `substantive`, optional `timestampPrecision`
- grouping: `workstreams`, optional `pullRequestNumber`

Derived fields (`category`, `outcome`, `substantive`, `groupKey`) are recomputed by
`normalizeEvent`. Do not add fields that cannot be justified from public evidence.

`data/activity-data.json` is the canonical recent event store and must include
`coverage` with source statuses. `data/activity-extended.json` carries older events and
is lazy-loaded. `personal-contributions.json` stores contribution ids; join them with
the activity payloads by id.

## Screenshot Policy

- Capture screenshots only for repos with a valid homepage URL or GitHub Pages indicator.
- Keep capture count bounded via MAX_SCREENSHOTS.
- Failures should be recorded in screenshots.json without failing the whole catalog unnecessarily.

## What To Avoid

- Reintroducing old reveal.js assets or build tooling.
- Committing secrets to the repository.
- Replacing curated summaries with low-quality autogenerated text without review.
- Converting this project into a server-rendered app unless explicitly requested.
- Publishing private or authenticated-only data, including notifications, private
  issues, or security alerts.
- Adding daily cron jobs, hosted LLM inference, or continuous polling without a
  documented need and cost estimate.
- Creating one HTML page per repository (thin duplicate pages).
- Inventing next actions, accomplishments, or urgency scores that the evidence does not
  support.
- Hand-editing generated activity HTML or reports.
